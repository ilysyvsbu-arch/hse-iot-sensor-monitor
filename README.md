# IoT Sensor Monitor API

REST-сервис на FastAPI для приёма, временного хранения в оперативной памяти,
фильтрации и анализа показаний температурных IoT-датчиков.

Сервис предназначен для системных администраторов и инженеров инфраструктуры,
которым нужно отслеживать перегрев оборудования и получать статистику по датчикам.

**Ограничение:** данные хранятся в памяти процесса. После перезапуска приложения
добавленные показания теряются, а сервис возвращается к начальному набору
демонстрационных данных. База данных в этой учебной версии не используется.

## Структура проекта

- `app_final.py` — основной код FastAPI-приложения.
- `test_app.py` — автоматические тесты.
- `requirements.txt` — основные зависимости.
- `requirements-dev.txt` — зависимости для разработки и тестирования.
- `.env.example` — пример переменных окружения.
- `.gitignore` — исключения для Git.
- `.github/workflows/ci.yml` — настройки GitHub Actions.

## 1. Создание окружения и установка зависимостей

Клонируйте репозиторий:

```bash
git clone https://github.com/ilysyvsbu-arch/hse-iot-sensor-monitor.git
cd hse-iot-sensor-monitor
```

Создайте виртуальное окружение на macOS или Linux:

```bash
python3 -m venv .venv
source .venv/bin/activate
```

Установите зависимости:

```bash
python -m pip install -r requirements-dev.txt
```

## 2. Переменные окружения

| Переменная | Назначение | Значение по умолчанию |
|---|---|---|
| `APP_VERSION` | Версия приложения | `1.0.0` |
| `MAX_TEMP_THRESHOLD` | Порог температуры для тревоги, °C | `35.0` |

Пример настройки в терминале macOS/Linux:

```bash
export APP_VERSION="1.0.0"
export MAX_TEMP_THRESHOLD="35.0"
```

Настройки можно изменить перед запуском приложения. Если переменные не заданы,
приложение использует значения по умолчанию.

Файл `.env.example` содержит примеры настроек. Приложение автоматически не загружает
этот файл, поэтому переменные нужно задавать в окружении терминала.

## 3. Запуск приложения

Запуск без автоматической перезагрузки:

```bash
uvicorn app_final:app --host 127.0.0.1 --port 8000
```

Интерактивная документация API:

http://127.0.0.1:8000/docs

## 4. Основные маршруты

| Метод | Маршрут | Назначение |
|---|---|---|
| `GET` | `/health` | Проверка работоспособности сервиса |
| `GET` | `/version` | Версия приложения и порог температуры |
| `POST` | `/readings` | Добавление показания датчика |
| `GET` | `/readings` | Получение и фильтрация показаний |
| `GET` | `/sensors` | Список датчиков и сводная информация |
| `GET` | `/sensors/{sensor_id}/stats` | Статистика конкретного датчика |

Для фильтрации показаний поддерживаются параметры `location` и `alert_only`.

Пример запроса:

```bash
curl "http://127.0.0.1:8000/readings?alert_only=true"
```

## 5. Автоматические тесты

Запустите тесты командой:

```bash
python -m pytest -v
```

Тесты проверяют работоспособность сервиса, получение версии, список датчиков,
добавление и фильтрацию показаний, обработку некорректных данных и статистику.

## 6. Проверка и диагностика

Проверка работоспособности:

```bash
curl http://127.0.0.1:8000/health
```

Ожидаемый ответ:

```json
{"status":"ok"}
```

Проверка версии и конфигурации:

```bash
curl http://127.0.0.1:8000/version
```

Получение списка датчиков:

```bash
curl http://127.0.0.1:8000/sensors
```

Получение статистики датчика:

```bash
curl http://127.0.0.1:8000/sensors/srv-01/stats
```

Добавление тестового показания:

```bash
curl -i -X POST http://127.0.0.1:8000/readings \
  -H "Content-Type: application/json" \
  -d '{"sensor_id":"test-01","location":"Lab","temperature":42,"humidity":30}'
```

При превышении температурного порога приложение записывает предупреждение в лог.
Логи запуска, запросов и ошибок выводятся в терминал, из которого запущен сервис.

Если для указанного датчика нет показаний, маршрут статистики возвращает HTTP 404.

## 7. GitHub Actions

При отправке изменений в репозиторий GitHub Actions автоматически устанавливает
зависимости, запускает тесты и после успешной проверки загружает артефакт приложения.

Результаты проверок доступны во вкладке Actions репозитория.

## 8. Ограничения

Сервис использует демонстрационный набор данных в оперативной памяти.
Добавленные показания не сохраняются после перезапуска приложения.

В проекте не используются база данных, Docker и внешние облачные сервисы.
