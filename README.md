# IoT Sensor Monitor API

REST-сервис на FastAPI для сбора, хранения, фильтрации и анализа показаний температурных IoT-датчиков (серверные комнаты, офисы, лаборатории). Предназначен для системных администраторов и инженеров инфраструктуры, которым нужно отслеживать перегрев оборудования и получать статистику по датчикам.

## Структура проекта
* `app_final.py` — основной код FastAPI-приложения.
* `test_app.py` — автоматические тесты (`pytest`).
* `requirements.txt` / `requirements-dev.txt` — зависимости проекта.
* `.env.example` — пример файла с переменными окружения.
* `.github/workflows/ci.yml` — конфигурация CI и сборки артефакта в GitHub Actions.

## 1. Создание окружения и установка зависимостей

Клонируйте репозиторий и создайте виртуальное окружение:

```bash
git clone [https://github.com/ilysyvsbu-arch/hse-iot-sensor-monitor.git](https://github.com/ilysyvsbu-arch/hse-iot-sensor-monitor.git)
cd hse-iot-sensor-monitor
python3 -m venv .venv
```

Активируйте окружение:
* **Linux / macOS:** `source .venv/bin/activate`
* **Windows (PowerShell):** `.venv\Scripts\Activate.ps1`

Установите зависимости:

```bash
pip install -r requirements-dev.txt
```

## 2. Переменные окружения

| Переменная | Описание | По умолчанию |
| :--- | :--- | :--- |
| `APP_VERSION` | Версия приложения | `1.0.0` |
| `MAX_TEMP_THRESHOLD` | Порог температуры в °C для срабатывания тревоги (`alert=True`) | `35.0` |

Задать переменные перед запуском можно в терминале:
* **Linux / macOS:** `export MAX_TEMP_THRESHOLD=30.0`
* **Windows (PowerShell):** `$env:MAX_TEMP_THRESHOLD="30.0"`

## 3. Запуск приложения и документация `/docs`

### Режим разработки (с автоперезагрузкой):

```bash
uvicorn app_final:app --reload --host 127.0.0.1 --port 8000
```

### Обычная работа приложения (без `--reload` для эксплуатации):

```bash
uvicorn app_final:app --host 0.0.0.0 --port 8000
```

После запуска интерактивная документация Swagger UI доступна в браузере по адресу:
* **Swagger UI:** http://127.0.0.1:8000/docs

## 4. Основные маршруты

| Метод | Маршрут | Описание |
| :--- | :--- | :--- |
| `GET` | `/health` | Проверка работоспособности сервиса |
| `GET` | `/version` | Текущая версия приложения и порог температуры |
| `POST` | `/readings` | Добавление нового показания датчика |
| `GET` | `/readings` | Список показаний с фильтрацией по `location` и `alert_only` |
| `GET` | `/sensors/{sensor_id}/stats` | Расчёт статистики (мин, макс, средняя температура) по датчику |

## 5. Запуск автоматических тестов

Для запуска тестов выполните команду:

```bash
python -m pytest -v
```

## 6. Проверка и диагностика

1. **Проверка работоспособности (`/health`):**
   ```bash
   curl [http://127.0.0.1:8000/health](http://127.0.0.1:8000/health)
   ```
   *Ожидаемый ответ:* `{"status":"ok"}`

2. **Проверка версии и конфигурации (`/version`):**
   ```bash
   curl [http://127.0.0.1:8000/version](http://127.0.0.1:8000/version)
   ```
   *Ожидаемый ответ:* `{"version":"1.0.0","max_temp_threshold":35.0}`

3. **Где смотреть логи:**
   * При запуске сервиса все события (`INFO`, `WARNING`, `ERROR`) выводятся в стандартный поток вывода терминала (`stdout`) с временными метками.
   * При превышении порога температуры в консоли появляется запись уровня `[WARNING] ALERT! High temperature...`, а при запросе несуществующего датчика — `[ERROR] Sensor '...' not found`.
